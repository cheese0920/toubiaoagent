# 技术投标文件质量门禁与审查规则

## 1. 目的与适用范围

本规则用于技术投标文件初稿、技术偏差表及其导出物的自动审查和人工复核。目标是在交付或导出前识别评分项遗漏、跨标包污染、历史项目残留、未确认承诺、技术偏差冲突、引用不可追溯及格式不完整等风险。

本规则不用于商务标、报价标或资格审查材料。所有通过门禁的文件仍须标记为“初稿”，并提示人工复核。

## 2. 审查输入与基线

执行审查前应形成不可混用的审查基线：

- 当前项目白名单：项目名称、采购人/建设单位、采购编号、允许出现的简称。
- 当前标包白名单：标包编号、标包名称、服务范围、交付物、服务期和适用技术规范。
- 排除清单：其他标包名称、专属服务、专属评分项和专属交付物。
- 评分基线：评分项编号、分值、评分标准、证明材料要求和目标响应章节。
- 要求基线：招标文件及技术规范中的强制要求、允许偏差和禁止偏差。
- 来源索引：来源文件标识、版本、页码、章节路径和原文定位信息。
- 承诺确认清单：经授权确认的人员、数量、时限、周期、驻场、免费服务和额外履约承诺。
- 格式基线：必备章节、目录层级、表格字段、页眉页脚、命名和导出格式要求。

缺少当前项目、当前标包或评分基线时，不得执行最终放行。

## 3. 严重级别与阻断策略

| 级别 | 含义 | 默认处置 | 放行条件 |
| --- | --- | --- | --- |
| `BLOCKER` | 投错标包、实质性负偏差、虚假或未经证实承诺等可能导致废标或重大履约风险的问题 | 阻断导出与交付 | 修复后重新全量审查；不得仅以人工备注豁免 |
| `CRITICAL` | 直接影响评分、响应完整性或内容真实性的高风险问题 | 阻断正式导出；允许生成带水印的内部审查稿 | 修复，或由指定审批角色书面确认后重新审查 |
| `MAJOR` | 可能造成扣分、歧义、追溯困难或格式不合规的问题 | 阻断交付；可生成内部审查稿 | 修复，或记录有期限的人工豁免 |
| `MINOR` | 不影响实质响应但降低一致性、可读性或专业性的瑕疵 | 不阻断导出，进入整改清单 | 建议交付前修复 |
| `INFO` | 审查提示、统计信息或无法自动判定的观察项 | 不阻断 | 人工按需复核 |

### 3.1 门禁决策

- `REJECT`：存在任一未解决的 `BLOCKER`，或门禁基线缺失。
- `REVIEW_REQUIRED`：不存在 `BLOCKER`，但存在未解决的 `CRITICAL` 或 `MAJOR`。
- `PASS_WITH_WARNINGS`：仅存在 `MINOR`、`INFO` 或已批准且未过期的豁免项。
- `PASS`：所有适用规则通过，且无未解决发现项。

### 3.2 豁免约束

- `BLOCKER` 不允许通过普通人工豁免放行。
- 豁免必须记录审批人、审批角色、原因、证据、适用版本和失效时间。
- 文档内容或来源基线变化后，原豁免自动失效。
- “待确认”“后续补充”“暂按此执行”不能视为有效豁免。

## 4. 质量门禁规则

### 4.1 评分覆盖

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `SCAPP-001` | 多组评分标准是否逐组记录适用标包范围原文 | `CRITICAL` | 未记录适用范围原文时，不得进入评分拆解 |
| `SCAPP-002` | 当前标包是否只选中一组评分标准且经人工确认 | `BLOCKER` | 未选中、选中多组或未经确认均阻断 G1 |
| `SCAPP-003` | 选中评分组是否声明适用于当前标包编号或名称 | `BLOCKER` | 疑似套用其他标包评分标准时阻断后续编写 |
| `SC-001` | 每个评分项是否映射到至少一个明确响应章节 | `CRITICAL` | 未映射即阻断正式导出 |
| `SC-002` | 响应章节是否覆盖评分标准中的全部子要求和关键词 | `MAJOR`；高分值核心项为 `CRITICAL` | 输出缺失子要求，不得以泛化表述判定覆盖 |
| `SC-003` | 要求的证明材料、图表、案例或附件是否存在且可定位 | `CRITICAL` | 缺少必需证明材料时阻断 |
| `SC-004` | 评分项响应是否与当前标包服务范围一致 | `BLOCKER` | 使用其他标包内容响应时阻断 |
| `SC-005` | 评分覆盖率、分值覆盖率是否达到配置阈值 | `MAJOR`；未达到强制阈值为 `CRITICAL` | 同时报告“项数覆盖率”和“分值覆盖率” |

覆盖判定必须基于“评分项编号 + 子要求 + 响应位置 + 证据位置”的映射，不得仅按关键词命中判定已覆盖。

### 4.1A 资料可读性与转换状态

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `SRCREADY-001` | 招标文件、技术规范书等核心依据资料是否登记在 `inventory/source-readiness.json` | `BLOCKER` | 核心依据资料未登记时 G0 不得通过 |
| `SRCREADY-002` | 核心依据资料正文、关键表格、条款和章节结构是否可稳定解析或已人工摘录复核 | `BLOCKER` | 不可稳定解析且未进入人工摘录模式时，不得启动自动正文生成 |
| `SRCREADY-003` | `.doc`、扫描件、图片型 PDF、加密文件是否记录解析/转换尝试、解析可信度和处置结果 | 参考材料为 `MAJOR`；影响核心依据时为 `BLOCKER` | 不按扩展名默认阻断；核心依据不可读才阻断，历史材料不可读只降级或排除出 RAG |
| `SRCREADY-004` | 来源索引是否引用转换后的有效版本，并保留原始文件路径 | `MAJOR` | 转换后版本未绑定原件时进入人工复核 |

### 4.1B 要求逐条拆解与特殊标记

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `REQ-001` | 每个可独立判断是否响应的条件是否单独形成原子要点 | `CRITICAL` | 复合条件未拆分时退回重新拆解 |
| `REQ-002` | 每条原子要点是否保留要求原文、来源文件、页码或章节路径 | `CRITICAL` | 无法追溯的要点不得进入章节任务 |
| `REQ-003` | 表格、脚注、附件、图片及格式说明中的要求是否纳入台账 | `CRITICAL` | 存在遗漏时 G1 不得通过 |
| `REQ-004` | `*`、`⭐`、加粗、下划线、醒目色等标记是否原样记录 | `MAJOR`；涉及强制或否决含义时为 `CRITICAL` | 不得丢失视觉标记 |
| `REQ-005` | `*`、`⭐` 的含义是否有文件说明或人工确认依据 | `CRITICAL` | 不得仅凭符号自行解释 |
| `REQ-006` | 废标、否决、无效投标、投标无效、不予受理条款是否逐条记录触发条件与后果原文 | `BLOCKER` | 任一遗漏或未确认均阻断后续编制 |
| `REQ-007` | 每条原子要点是否明确适用标包、主响应章节和证据要求 | `CRITICAL` | 未映射要点不得进入 G2 |
| `REQ-008` | 当前标包评分组是否按逻辑来源片段、适用规则、排除规则和覆盖关系完成组合确认 | `BLOCKER` | 不得硬编码页码或强制单组；未确认组合不得进入章节规划 |
| `REQ-009` | 每个评分项是否绑定已选中的 `scoring_group_id` 和 `source_segment_id` | `BLOCKER` | 来自未选中、已排除、冲突或被覆盖评分组的评分项立即阻断 |
| `REQ-010` | 每个必答要求是否形成已确认的 `response_item_id` 和我司响应口径 | `BLOCKER` | 未转换、未确认或仍只抄招标原文时不得进入 G2 |

### 4.1C 章节规划与任务拆分

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `PLAN-001` | 一级章节名称、顺序和层级是否来自招标文件技术投标格式原文 | `BLOCKER` | 未锁定格式原文或擅自改动一级章节时，G2 不得通过 |
| `PLAN-002` | 评分项是否映射到招标格式章节内，并指定主响应章节 | `CRITICAL` | 评分项未映射或仅映射到自造章节时退回章节规划 |
| `PLAN-003` | 技术规范书和服务范围要求是否映射到章节规划表 | `CRITICAL` | 核心技术要求无章节承接时，不得生成 `chapter-realizer-*` 任务 |
| `PLAN-004` | 高分值或大体量评分项是否拆分为可执行写作任务 | `MAJOR`；导致遗漏风险时为 `CRITICAL` | 单个任务上下文过大或任务范围泛化时重新拆分 |
| `PLAN-005` | 格式要求与评分项结构不一致时，是否以投标文件格式为一级框架 | `BLOCKER` | 用评分项结构替代招标格式章节时阻断 |
| `PLAN-006` | 二级标题是否按当前标包适用的详细评审分项要素顺序映射 | `MAJOR`；导致评分点无落位时为 `CRITICAL` | 二级标题套用通用模板或未记录评分分项来源时退回章节规划 |
| `PLAN-007` | 三级标题是否从评分描述、得分条件、证明材料要求或关键词中拆解 | `MAJOR`；高分值核心项为 `CRITICAL` | 不得以“总体思路、保障措施、实施路径”等泛化标题替代具体得分点 |
| `PLAN-008` | 三级以下标题是否结合项目实际、技术规范书、服务范围和交付物细化 | `MAJOR` | 缺少项目依据或只复用历史模板时退回重拆 |
| `PLAN-009` | 每个父标题下同级子标题数量是否合理 | `MAJOR`；超过 5 个为 `CRITICAL` | 原则上 3-4 个，最多不超过 5 个；过细或过散时合并为可执行结构 |
| `PLAN-010` | 项目建设思路、服务方案、实施方案等通用章节是否已完成评分项下钻映射 | `CRITICAL` | 通用章节未形成“评分分项 → 评分描述关键词 → 项目实际细化”的标题链时不得派发 `chapter-realizer-*` |
| `PLAN-011` | 是否保留最高得分档原文并拆成评分内容对象、质量标准、全局约束和证明材料要求 | `CRITICAL` | 未完成最高档原子化时不得进入章节规划 |
| `PLAN-012` | 每个评分内容对象是否与一个且仅一个三级主响应标题逐项对应，且标题忠实保留原文响应对象 | `CRITICAL` | 缺失、错位、泛化改名或出现多个主响应标题时退回重拆 |
| `PLAN-013` | 质量程度词、全局约束和评审方式是否被错误生成为独立标题 | `CRITICAL` | 将“详细性、合理性、结合项目实际、横向比较”等单独作为标题时退回重拆 |
| `PLAN-014` | 组织、进度、质量、风险、交付物等交叉内容是否设置主响应章节、关联章节和去重策略 | `CRITICAL` | 机械删除、无主响应、关联章节不存在或整段重复时不得派发任务 |
| `PLAN-015` | 详细技术方案是否按本项目服务实施闭环展开 | `CRITICAL` | 将服务类技术方案窄化为拟建系统功能或架构说明，遗漏组织资源、实施保障或成果验收支撑时退回重拆 |
| `PLAN-016` | 每个已确认 `response_item_id` 是否映射到主响应章节、关联章节和写作任务 | `BLOCKER` | 响应口径无正文落点或进入错误任务时不得派发 |

章节规划表必须先于章节任务书形成。`chapter-realizer-*` 任务只能从已确认的 `planning/chapter-plan.json` 派生，不得由总控或历史模板直接生成。

### 4.1D 章节依据包与段落计划

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `GROUND-001` | 每个章节任务是否声明并生成唯一的 `grounding_pack_file` 与 `paragraph_plan_file` | `BLOCKER` | 缺少任一产物不得启动初稿生成 |
| `GROUND-002` | 依据包是否绑定任务内全部评分项、`score_atom`、技术要求和废标/否决条款 | `CRITICAL` | 任一遗漏退回 `content-grounder` |
| `GROUND-003` | 项目事实是否逐项绑定当前项目来源，知识卡是否仅作结构和表达参考 | `BLOCKER` | 知识卡或历史正文被当作事实来源时阻断 |
| `GROUND-004` | 每个三级或四级主响应标题是否至少形成一个段落计划 | `CRITICAL` | 标题无写作计划时不得生成正文 |
| `GROUND-005` | 每个段落计划是否包含项目实际、执行动作、控制节点、交付成果和来源 | `CRITICAL` | 任一关键字段缺失时退回补齐 |
| `GROUND-006` | 依据包是否仍有 `open_questions` 或待确认占位内容 | `CRITICAL` | 未关闭问题不得转交 `chapter-realizer-*` |
| `GROUND-007` | 依据包和段落计划是否携带任务绑定的 `canonical_response`、`fixed_elements`、`allowed_expansion` 和 `forbidden_changes` | `BLOCKER` | 缺少响应边界时不得生成正文 |

### 4.1E 章节初稿真实落位

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `DRAFT-001` | 章节初稿是否严格使用任务书中的 `planned_outline` | `CRITICAL` | 缺少规划标题、标题顺序错误或自行重构标题时，不得进入扩写 |
| `DRAFT-002` | 每个评分项是否在初稿或证据文件中有明确响应位置 | `MAJOR`；高分值核心项为 `CRITICAL` | 不得以泛化段落替代评分点落位 |
| `DRAFT-003` | 每个原子要求是否在初稿或证据文件中有明确响应位置或待人工确认标记 | `MAJOR`；强制项为 `CRITICAL` | 无响应位置时退回初稿生成 |
| `DRAFT-004` | 初稿是否维护 evidence 文件并记录来源引用 | `MAJOR`；关键事实无来源为 `CRITICAL` | 证据链不完整时不得进入扩写 |
| `DRAFT-005` | 初稿是否出现页级模板轮转、同义反复或空泛堆砌 | `MAJOR` | 初稿生成器不得以凑页数替代真实展开 |
| `DRAFT-006` | 初稿生成器是否越权承担扩写深化职责 | `MAJOR` | 过度扩写、改变承诺边界或引入无来源细节时退回重写 |
| `DRAFT-007` | 每个段落计划中的执行动作、控制节点或交付成果是否在初稿中真实落位 | `MAJOR`；核心评分项为 `CRITICAL` | 只写原则和口号、没有措施颗粒度时退回重写 |
| `DRAFT-008` | 是否出现首先、其次、此外、综上等禁用模板化连接词 | `MAJOR` | 命中后定点改写，不得以连接词代替真实逻辑 |
| `DRAFT-009` | 强事实或承诺是否在 evidence 的 `supported_claims` 中逐项绑定来源 | `CRITICAL`；造成额外履约义务时为 `BLOCKER` | 泛化来源不能替代逐项证据 |
| `DRAFT-010` | 初稿是否通过当前任务适用的废标/否决检查 | `BLOCKER` | 未通过 `check-rejection` 不得进入扩写 |
| `DRAFT-011` | 初稿是否使用已确认的我司响应口径，并在 evidence 中绑定 `response_item_ids` | `BLOCKER` | 只抄“投标人应”或未保留 canonical_response 时退回重写 |
| `DRAFT-012` | 正文是否改变响应口径的责任主体、条件、范围、数字、单位或承诺强度 | `BLOCKER` | 把采购方义务改成我司义务、把阶段现场联络扩成全周期驻场等立即阻断 |

章节初稿由 `chapter-realizer-*` 或兼容的 `chapter-writer-*` 生成；扩写深化必须交给 `chapter-expander-*`，不得将两个职责合并为一个不可审查的大生成器。

### 4.2 跨标包污染

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `PKG-001` | 正文、表格、页眉页脚或附件中出现其他标包编号、名称 | `BLOCKER` | 命中排除清单即阻断 |
| `PKG-002` | 出现其他标包专属服务、交付物、技术路线或评分项 | `BLOCKER` | 即使未出现标包名称，也按语义冲突阻断 |
| `PKG-003` | 当前标包名称、编号或范围在不同位置表述不一致 | `CRITICAL` | 以当前标包白名单为准修复 |
| `PKG-004` | 引用了跨标包共用内容但未完成适配 | `MAJOR` | 标记具体未适配段落并人工复核 |

跨标包内容默认禁止复用。只有通用管理机制、质量控制和归档流程等可在去除标包专属信息并完成适配后复用。

### 4.2A 历史材料轻量 RAG 准入

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `RAG-001` | 历史技术标和技术支撑材料是否完成章节级、段落级切片并记录来源 | `MAJOR` | 未记录来源的片段不得进入任务书 |
| `RAG-002` | 历史片段是否完成去项目化和残留信息检测 | `BLOCKER` | 未清洗片段不得进入 writer 上下文 |
| `RAG-003` | 片段状态是否为 `AVAILABLE`、`NEEDS_CONFIRMATION` 或 `DISABLED` | `CRITICAL` | 状态缺失或非法时不得使用 |
| `RAG-004` | `NEEDS_CONFIRMATION` 片段是否已由用户人工确认 | `CRITICAL` | 未确认不得进入正文生成 |
| `RAG-005` | `DISABLED` 片段是否被分配给 `chapter-realizer-*` 或出现在正文上下文 | `BLOCKER` | 命中即阻断并回收任务书 |
| `RAG-006` | `chapter-realizer-*` 是否只使用 cleaned_content，而非 original_content | `BLOCKER` | 直接使用历史原文时阻断 |

MVP 阶段不要求建设复杂片段库。片段准入只检查基础字段、清洗结果、风险标记和三态状态；后续可在历史材料规模扩大后再增加标签、复用等级、人工审核和模板沉淀能力。

### 4.3 历史项目残留

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `HIS-001` | 出现非当前项目名称、采购人、建设单位、采购编号 | `BLOCKER` | 命中历史项目实体即阻断 |
| `HIS-002` | 出现与当前要求冲突的历史合同周期、服务期或里程碑日期 | `BLOCKER` | 冲突即阻断 |
| `HIS-003` | 出现未经确认的历史人员、团队人数、案例、平台或工具名称 | `CRITICAL` | 移除、泛化或经人工确认 |
| `HIS-004` | 出现历史页眉页脚、文件名、图表标题、图片水印或元数据 | `MAJOR`；指向其他项目时为 `BLOCKER` | 扫描正文外对象及导出文件属性 |
| `HIS-005` | 复用内容保留“本项目已实施”“现网已部署”等历史完成态表述 | `CRITICAL` | 需改写为当前项目可验证的响应表述 |

历史材料复用等级建议：

- `A`：通用管理机制、质量控制、归档流程，可适配后复用。
- `B`：行业通用技术路线、实施方法、服务流程，须按当前标包改写。
- `C`：团队、人员、案例、响应时限，须人工确认后使用。
- `D`：项目名称、客户、合同周期、具体承诺，禁止直接复用。
- `E`：其他标包专属内容，默认禁止。

### 4.4 要求—响应口径与未确认承诺

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `COM-001` | 无材料证明或授权确认的强承诺，如“保证”“确保”“无条件”“全部满足” | `BLOCKER` | 删除、降级表述或补充有效确认 |
| `COM-002` | 未确认的响应时间、交付周期、服务期、驻场安排或免费服务 | `CRITICAL` | 与 `response-register` 比对，未命中则阻断正式导出 |
| `COM-003` | 未确认的人员姓名、资质、团队配置、人数或到岗安排 | `CRITICAL` | 不得推断或编造 |
| `COM-004` | 未确认的系统功能、接口能力、兼容范围、性能指标或额外服务 | `CRITICAL` | 需要来源证据或授权确认 |
| `COM-005` | 承诺强度高于招标要求或来源材料 | `MAJOR`；造成额外履约义务时为 `CRITICAL` | 标注原要求与增强承诺差异 |
| `COM-006` | 供应商义务是否转换为可直接写入的“我司将……”响应口径 | `BLOCKER` | 招标要求视角未转换时不得进入正文 |
| `COM-007` | 采购方义务、禁止性要求和评分期待是否采用正确响应模式 | `BLOCKER` | 分别使用配合理解、禁止性响应和方案响应，禁止责任转移 |
| `COM-008` | 扩写是否超出 `allowed_expansion` 或命中 `forbidden_changes` | `BLOCKER` | 保留 `fixed_elements`，删除范围扩大或额外承诺 |

响应检查应识别责任主体、触发条件、范围、数字、时间单位、绝对化措辞和履约动作，并将正文表述关联到要求原文、`response_item_id`、来源证据和确认记录。

### 4.5 技术偏差一致性

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `DEV-001` | 技术偏差表中的偏差结论是否有招标要求和响应证据支撑 | `CRITICAL` | 无证据不得自动认定为“无偏差” |
| `DEV-002` | 偏差表与正文、响应表、实施方案、`response-register` 是否一致 | `BLOCKER` | 结论冲突或范围冲突即阻断 |
| `DEV-003` | 是否存在未确认负偏差、遗漏偏差或弱化响应 | `BLOCKER` | 必须由授权角色确认并处理 |

### 4.5A 废标与否决风险

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `REJ-001` | 任务绑定的废标、否决、无效投标条款是否在初稿、扩写稿、证据和合稿中可定位 | `BLOCKER` | 任一任务引用未登记条款或条款失去响应位置时阻断 |
| `REJ-002` | 正文是否出现负偏差、无法满足、另行收费、备选方案、不承担等高风险表述 | `BLOCKER` | 立即停止合稿并核对招标原文、技术偏差表和授权口径 |
| `REJ-003` | 合规性说明是否被误判为风险，例如“不得存在实质性不响应” | `MAJOR` | 由确定性上下文规则先消除误报，剩余项转人工判断 |
| `REJ-004` | 技术偏差表与正文、响应表和承诺口径是否一致 | `BLOCKER` | 不得自动确认负偏差或以正文弱化偏差结论 |
| `DEV-004` | 正偏差是否实质形成未经确认的额外承诺 | `CRITICAL` | 转入承诺审查，未确认不得放行 |
| `DEV-005` | “无偏差”“完全响应”等结论是否逐条覆盖强制要求 | `CRITICAL` | 泛化结论不能替代逐条核验 |

偏差记录必须至少包含要求原文、来源位置、响应说明、响应位置、偏差类型、偏差原因和确认状态。

### 4.6 引用溯源

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `SRC-001` | 关键结论、参数、业绩、资质和承诺是否具备来源记录 | `CRITICAL` | 无来源的事实性关键结论阻断正式导出 |
| `SRC-002` | 来源记录是否包含文件标识、版本、页码或章节路径 | `MAJOR` | 定位信息不足则进入整改 |
| `SRC-003` | 引用内容是否与来源原文一致，是否存在断章取义或数值变化 | `BLOCKER`；一般文字偏差为 `CRITICAL` | 数值、范围、否定词或条件变化按阻断处理 |
| `SRC-004` | 来源文件版本是否为当前有效版本 | `CRITICAL` | 过期、撤回或未知版本不得作为关键证据 |
| `SRC-005` | 同一结论的多个来源是否互相冲突 | `CRITICAL` | 明确冲突并要求人工裁决 |

引用链应支持从“响应结论”追溯到“来源文件 + 版本 + 页码/章节 + 原文摘录”，并支持反向定位到使用该来源的响应章节。

### 4.7 格式完整性

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `FMT-001` | 必备章节、表格、附件和签章占位是否齐全 | `CRITICAL`；非强制项为 `MAJOR` | 按格式基线逐项核验 |
| `FMT-002` | 目录、标题层级、章节编号、图表编号和交叉引用是否连续有效 | `MAJOR` | 输出断号、重复号和失效引用 |
| `FMT-003` | 技术偏差表、评分响应索引等关键表格字段是否完整 | `CRITICAL` | 缺少关键字段时阻断正式导出 |
| `FMT-004` | 项目名称、标包名称、日期、版本号在封面、页眉页脚和正文是否一致 | `CRITICAL` | 与白名单不一致时阻断正式导出 |
| `FMT-005` | 是否存在空白页、截断表格、溢出文本、缺图、乱码或不可读对象 | `MAJOR`；关键内容不可读为 `CRITICAL` | 必须对最终导出物执行视觉检查 |
| `FMT-006` | 文件命名、格式、页码、字体和版式是否符合招标要求 | `MAJOR`；强制格式不符为 `CRITICAL` | 以格式基线判定 |

### 4.8 受控扩写质量

| 规则 ID | 检查内容 | 严重级别 | 判定与处置 |
| --- | --- | --- | --- |
| `EXP-001` | 扩写稿标题、标题层级、分段顺序和段落数量是否与原文一致 | `CRITICAL` | 任一结构变化均退回扩写，不得进入合稿 |
| `EXP-002` | 全文及各正文段落扩写比例是否达到任务书要求 | `MAJOR` | 全文控制在原文 2.7–3.5 倍，各段不低于 2.5 倍 |
| `EXP-003` | 官样文风、我司视角、核心细节和证据引用是否完整保留 | `CRITICAL` | 视角改变、核心细节或引用丢失时阻断合稿 |
| `EXP-004` | 扩写是否引入未经来源支持的新事实、新参数或新承诺 | `BLOCKER` | 删除新增内容并重新执行承诺与溯源审查 |
| `EXP-005` | 段首段尾是否出现总结性话语，是否存在同义反复或空泛堆砌 | `MAJOR` | 退回改写并人工抽查上下文衔接和逻辑严谨性 |
| `EXP-006` | 扩写是否只围绕段落计划中已有对象、动作、控制点、成果和证据加厚 | `CRITICAL` | 偏离段落计划或补新事实时退回原任务 |
| `EXP-007` | 扩写是否出现禁用连接词、无来源承诺或废标风险 | `BLOCKER`；仅文风词命中为 `MAJOR` | 同时执行 `check-expansion` 与 `check-rejection` |
| `EXP-008` | 自动扩写整改是否超过两轮 | `CRITICAL` | 两轮仍未通过时停止循环并转人工处理 |
| `EXP-009` | 扩写稿是否保持全部 `response_item_id`、`canonical_response` 和 `fixed_elements` | `BLOCKER` | 条件、范围、数字、单位、责任主体或承诺强度变化时退回扩写 |

## 5. 执行顺序与审查范围

建议按以下顺序执行，以降低误报并尽早阻断高风险输出：

1. 校验审查基线、文件版本和当前标包身份。
2. 扫描跨标包污染与历史项目残留。
3. 审查未确认承诺和技术偏差一致性。
4. 建立评分项、响应章节、证明材料之间的覆盖映射。
5. 验证关键结论和引用链。
6. 检查结构、表格和最终导出物的格式完整性。
7. 汇总发现项、豁免项和门禁决策，并提示人工复核。

审查范围须覆盖正文、表格、脚注、批注、文本框、图片文字、页眉页脚、附件、文件名、文档属性和最终导出物。无法自动读取的对象必须生成 `INFO` 或更高级别的人工复核项，不得静默跳过。

## 7. 最低放行条件

正式导出和交付前必须同时满足：

- 当前项目、当前标包、评分和格式基线完整有效。
- 无未解决的 `BLOCKER`、`CRITICAL` 或 `MAJOR`。
- 每个评分项均有明确响应位置，必需证明材料均可定位。
- 无其他标包或历史项目核心信息残留。
- 所有强承诺均有来源证据或有效确认记录。
- 技术偏差表与正文一致，且不存在未确认负偏差。
- 所有关键事实和结论可追溯到有效来源。
- 最终导出物已完成格式和视觉完整性检查。
- 报告已明确提示人工复核，交付物已标记为“初稿”或按流程完成终审。
